# Milestones

What each milestone built, in the order it was built. The README says what the product is; this page says how it got there.

## 1. The maritime operations OS

The forecasting pipeline (IMF PortWatch port activity, Open-Meteo weather, GDELT and GDACS events, FRED macro), eleven specialist experts, HSMM regimes, a calibrated ensemble with walk-forward validation, a decision layer and route optimiser, the API cache and provenance export. On top of it: Global Eye (events corroborated, deduplicated and propagated through chokepoints and lanes onto ports), the port digital twin with a deterministic simulator and a policy benchmark, cargo transshipment feasibility, the advisory boundary (eleven states, role-gated, audited), agent orchestration with a Critic and an enforced approval ceiling, the MCP tool layer, the outcome ledger with calibration and contextual reliability, and digital-twin policy learning behind a promotion gate.

## 2. Live world fabric

The Signal Fabric: licence at product granularity with recorded evidence, and a resolver that refuses rather than degrades. The AISStream client with two state machines (the socket's health and the traffic source's honesty: `LIVE_AIS` only when valid observations arrive, `AIS_STALE` when they stop, never the replay by falling through). Entity fusion that never merges by name. Observed hulls placed on the world graph with placement confidence. The marine grid from Open-Meteo Marine with fetch age and coverage on every sample. The versioned live world with incremental cascade recompute. Scenario branches that never edit the observed world. The chart widened to the Cape.

## 3. Decision intelligence engine

The decision model: typed catalogue actions marked available or not with a reason; each option simulated on its own branch; hard constraints that reject rather than penalise; a Pareto frontier with named picks; a balanced ranking with its weights outside; Critic v2 naming the computation it read; a recommendation that is never dominated. The financial twin with public tariffs (JNPA, Chennai) cited to the page, an FX table that refuses to add currencies without an observation, and operator assumptions labelled on every figure they touch. Actors and the approval workflow into the advisory boundary. The decision ledger and decision learning. The first historical mission (Ever Given, Suez, March 2021) with no future leakage and a scorecard that applies the outcome to every option. The decision UI, the Copilot's "what should we do?", the mission replay screen.

## 4. Productisation and proof

One **WorldClock** in four modes (LIVE, REPLAY, HISTORICAL_MISSION, SCENARIO) that every temporal subsystem reads; the wall is read only where the wall is the subject, with a written reason, and a test scans the source for anything else. A **freshness coordinator** with a policy per artefact — SLA, lead, stale threshold, bounded backoff, dedupe, last-known-good, dependency invalidation — replacing the operator's memory of when the register lapses. **Telemetry** and admin diagnostics without secrets. A **deployment validator** that refuses a misleading configuration and `python -m portwatch.demo start`, one command that validates, refreshes, starts, verifies and prints the actual mode of every signal. `scripts/verify_live_ais.py`, the acceptance path for a real AIS key that SKIPs honestly without one. A **performance benchmark** (world builds to 10,000 hulls, cascades, attention, decisions, scenarios, the frontier, the Critic, missions, API percentiles) and a **decision benchmark** on a fixed seeded corpus across vessel, port and cargo that publishes where the optimiser loses. **Fifteen adversarial attacks** on the engine, two of which found gaps now closed: approval on a world that moved on, and a contested or stale observed subject. The **second mission** — Cyclone Biparjoy over Kandla and Mundra, June 2023 — with the world path that lets a port closure reach the ships bound for it, and the **mission comparison** that reads both missions the same way. **Structural trade exposure** (event → chokepoint → lane → port → commodity class, every link sourced, no volume) and the **security lens** (seven behaviour rules over observed AIS, UNAVAILABLE under the replay). The UI pass: a 10px typography floor, the action rail kept on screen at 768px, lens reports read from the API, the freshness table and the world clock on the status strip, the second mission and the comparison on the mission screen. The acceptance gate grown to thirty-nine claims. The two-minute demo driven end to end by `qa/executive-demo.mjs` and timed; the failure demo (`scripts/demo_failure.py`) that made AIS, money and the marine grid fail for real — and tightened readiness twice: a refused credential and a required grid that was never produced are now refusals. The README rewritten as a product story.

## 5. Release candidate

The freeze. No new product features; the one decision-quality weakness the benchmark had exposed fixed structurally: a **robust decision policy** (`decision/robust.py`) that evaluates every option under four labelled stress horizons for the claim's duration with the closure outcome model the mission scorecard scores by, decides by minimax regret with the current plan as a first-class candidate, and answers ACT, KEEP_CURRENT_PLAN with the contender's break-even closure length, or WAIT_FOR_MORE_INFORMATION when the branch point outlasts the next register refresh; reversibility on every option; the expected-value frontier kept beside it. The benchmark grown to five policies on three disjoint seeded corpora and a **decision-policy promotion gate** whose conditions were fixed before the held-out corpora ran; the robust policy cleared it on validation and on the untouched test corpus and is the engine's default, with a test that the default matches the published verdict. **Durable state** named and probed: `PORTWATCH_STATE_DIR` for the ledger, the advisory register and a journalled assumption file; a corrupt store refused at open, never replaced; a decision from before a restart served from the ledger read-only; `scripts/demo_restart.py` proving restart, corrupt ledger and corrupt cache behave as stated; the container recipe with one worker and a state volume. The **security freeze**: an identity seam with no default to command on administration surfaces and a `required` mode for a deployment behind a proxy, administrator standing derived from the role alone, learning and the process-wide cost basis for national command, every decision route scoped to the people it belongs to, an authorization matrix proved cell by cell, a fuzz suite that found six real faults, pip and npm audits. **Performance budgets** set from measurement with a gate and a CI-safe subset, and the discovery that Windows power-throttles a long-running process after a minute — the benchmark and the API now opt out. The status strip names the licence mode and the traffic truth. Fifteen canonical screenshots at three resolutions; the fifteen-minute frontend session measured for growth.
