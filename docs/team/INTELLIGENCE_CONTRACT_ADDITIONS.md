`DecisionEvidence.restrictionAsset` contains `{id, name, lat, lon, basis}`. `decisionLayers` emits its point through the existing `cascade` source. The internal `portwatch:focus-constraint` event carries this asset and its `period`; `useWorkspaceMap` adds a labelled point and focuses the existing chart, while the Global Intelligence dialog closes. The point comes from official MSI, not a generated shipping route, closure polygon or surveyed twin. Teammates can later replace this small event bridge with a shared typed selection contract.

Timeline marks add `restriction_start`, `restriction_end` and `passage_request`, each with explicit `subject`, `hours` from comparison origin and retained `at`. These are scheduled constraints, not observed movements, claim expiry or confirmed access. Preserve their distinctions in subsequent presentation work.

`operationalEpisode` is server-owned `{id, voyageLegId, namespace, vesselId, portCode, createdAt}`. ETA edits, refreshes and role copies preserve it. A distinct next call requires a confirmed Company request and stable `requestId`; repeated identical requests recover the same call, while conflicting reuse is rejected. Earlier comparisons and advisories remain inspectable.

The advisory's `approvedActionContract` and outcome's `simulatedAction` carry canonical action and metric basis hashes. A simulation identifies its call and selected action but has `actualExecutionAt: null` and `eligibleForRealTarget: false`. Do not use approval, acceptance or simulation as proof of real execution.

Operational inspection preserves all forecast vintages. Real scoring requires episode, executed action, action/metric basis hashes, explicit approved forecast cutoff, observation/availability times and suitable original records. One independent episode/metric counts once under the documented cutoff policy; conflicting records remain excluded. Old records without this identity remain unscored and inspectable.

Frozen feedback retains a global snapshot for audit, but continuation checks consumed assessment/applicability, originals, relevant active consumer-bound policies, expiry and voyage declarations. Global pending counts are not continuation dependencies. Current calculators bind no learned policy: weight 1, no correction, COLLECTING. Future calculators must explicitly bind actual consumed policy parameters; discovering a matching version in the ledger does not apply it.

Economic quotes and persistence forecasts remain inspectable. They cannot create vessel holds. No currency exposure amounts or settlement dates are invented; a future valuation contract must supply those inputs separately from reference rates and realized savings.

## October 17 public-port context and evidence dispositions

`GET /intelligence/operational-evidence` projects the existing public-port pilot's retained official Chennai/Paradip PDF rows and separately retained IMF daily aggregate receipts. Reads do not collect. The existing backend freshness coordinator owns collection and independent retries. Each product carries exact selectors, hash verification, printed report date, original first receipt, extraction availability, last check, missing clocks, collection failures and semantic limitations. A source date is not a precise publication instant. The corrected Chennai expected-arrival parser is versioned; corrected fields become available when re-extracted, rather than being backdated to the original receipt.

`OperationalEvidencePanel` mounts inside the existing `ShippingIntelligencePanel`. It adds evidence/record and owned-voyage selection, original download and a context inspection request. A different physical port requires explicit candidate-port context confirmation. The existing optional map-focus event accepts a canonical port point when available; it does not imply route membership or vessel identity. No protected role screen or twin geometry changes. OCEANS-X qualification is a separate inactive API candidate, with no account/key entry in the UI.

The existing review-task POST now accepts exactly one of `signalId`, `claimId` or `operationalEvidence: {product, portCode, snapshotId | receiptId, recordId}`. Company supplies its owned `vesselId`, stable `requestId` and `portContextConfirmed`. The existing task kind is retained; a context request sets `taskQuestion=INSPECT_PUBLISHED_PORT_CONTEXT_FOR_DECLARED_VOYAGE` and freezes its source, selected context and operational episode.

`POST /intelligence/review-tasks/{taskId}/dispositions` accepts `{requestId, operationalEvidence, dispositionType: CONTEXT_REVIEWED, contextConfirmed: true, note?}`. The server resolves the retained evidence selector; caller-supplied actual outcomes are rejected. Company or the task's scoped Port role may append a review; Vessel/Admin may inspect. The immutable ledger record retains original task, original hash, new evidence, actor, role, time and request identity. Retrying the same request recovers the same record, including after restart or an interrupted world-pointer update. GET tasks adds `dispositions`, `latestDispositionId` and a projected `CONTEXT_REVIEWED` status only when the frozen question was context inspection. Earlier source bodies remain unchanged.

Context review answers an operator inspection question. `sourceClaimStatus=UNRESOLVED`, `actualExecutionStatus=NOT_OBSERVED`, `eligibleForRealTarget=false` and `realResolvedTargetsAdded=0` remain separate. Aggregate calls are not individual AIS; publisher-reported arrivals are not all-fast; names/dimensions do not associate a fictional hull. Unsupported waiting, schedule, fuel, cost and safety consequences remain unavailable. This contract does not add a numerical advisory state machine.

## October 19 daily weather shadow analysis

`GET /weather/shadow` adds read-only error analysis from the retained public weather ledger/originals, with optional `portCode`, `variable`, `provider`, `horizon` and aware `asOf`. `WeatherShadowPanel` mounts inside the existing `WeatherVerificationPanel`, retaining the original Weather/Global Eye/Learning entry points. Responses carry versioned selection/adoption criteria, global independent outcome counts, exact-context metrics, chronological block membership/purges and SHA-linked source evidence. Counts across forecast horizons are not additive independent outcomes. Receipt-calendar horizon and exact lead hours remain distinct.

`mode=SHADOW_ONLY` and `decisionEligible=false` apply to every analysis/candidate. Retrospective candidates can be `COLLECTING`, `REJECTED` or `SHADOW_VALIDATED`; none is adopted here. A minimum of eight targets in each of four availability-purged blocks, strict greater-than-2% validation/evaluation improvement, independent calibration, genuinely prospective evidence and explicit scoped adoption are separate gates. Current daily frames/watch/arrival features consume raw values even for retained legacy mathematical `VALIDATED` candidates. Original prediction fields and old decision records remain inspectable. Hourly approach inputs and rejected neural/RL artifacts are unchanged. See `docs/WEATHER_SHADOW_ANALYSIS.md` for evidence identity and local validation.
